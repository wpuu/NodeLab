## 1a. Windows 前置条件（否则测试会以 `PRIVATE_DIR_UNSAFE`/`RECOVERY_REVIEW_REQUIRED` 误报 FAIL）

候选代码把私有根固定为 `E:\NodeLab.secrets\_runtime`，并对**已存在**的目录只做 ACL 读回校验、绝不修改其 ACL（见 [`NL-REVIEW-003`](../audits/NL-REVIEW-003-f1-f2a-candidate-review.md) B10）。执行前逐项核对：

1. **用非提权（非"以管理员身份运行"）的 PowerShell** 执行 §2 的命令。提权会话新建的对象所有者是 `BUILTIN\Administrators` 而不是当前用户 SID，所有者校验必然失败；这是误报，不是 ACL 缺陷。
2. **最简单的做法是不要预先创建** `E:\NodeLab.secrets` 或 `_runtime`：候选代码会自行创建并用 `icacls /inheritance:r /grant:r <用户SID>:(OI)(CI)F *S-1-5-18:(OI)(CI)F` 收紧。
3. 若 `E:\NodeLab.secrets` **已存在**（用户自己的秘密目录），它必须满足：所有者 = 当前用户 SID；已禁用继承；DACL 中**只有**当前用户与 `SYSTEM` 两条 Allow FullControl 且无继承 ACE；不是 junction/符号链接。可用下列命令**仅对该目录本身**（不递归、不触碰其中文件）整理：
   ```powershell
   $sid = [System.Security.Principal.WindowsIdentity]::GetCurrent().User.Value
   icacls E:\NodeLab.secrets /inheritance:r /grant:r "*${sid}:(OI)(CI)F" "*S-1-5-18:(OI)(CI)F"
   ```
   若该目录内已有真实文件而用户不愿改动其 ACL，返回 `BLOCKED_PRIVATE_ROOT_ACL` 交 Owner 决定，不要自行递归改权限。
4. `E:\NodeLab.secrets\_runtime` 若已存在，其中不得有上次崩溃的残留（无人持锁的 `<run_id>` 目录/`.lock` 文件、非本应用的文件），否则新运行返回 `RECOVERY_REVIEW_REQUIRED`；并发的活跃运行不算残留。残留由**用户本人**执行 `py -3 -m nodelab.cli recover --confirm`（需 `PYTHONPATH=E:\NodeLab\src`）回收：它只删除已验证归属的目录，只终止 pid+创建时间+可执行文件指纹与 marker 完全一致的孤儿子进程，不按进程名匹配、不碰用户自己的 Mihomo；输出为固定字段行，不含路径。执行者不得代为手工删除或 `taskkill`。
5. 卷必须是本机固定盘 NTFS（`DRIVE_FIXED`）；BitLocker 不影响，但网络映射盘、可移动盘、ReFS/exFAT 会被拒绝。

### 0b. 执行方式：单命令确定性脚本（取代逐条人工/代理操作）

`scripts/w1_gate.py` 把本任务 §1、§1a、§2 的全部检查编码为一条命令。Owner 只需在 Windows 上运行它，然后把结果块贴回。**脚本必须放在仓库工作树之外**（否则切换验证分支时可能把自己覆盖掉，脚本会自行检测并阻断 `BLOCKED_SCRIPT_INSIDE_WORKTREE`）。

脚本行为承诺（已在 Linux 上以模拟 origin + 旧 main 的工作副本做过 6 项自测）：

| 承诺 | 实现 |
| --- | --- |
| 绝不修复环境 | 不改 ACL、不 `git clean/reset/stash/rebase/merge/pull`、不 taskkill、不手工删除 |

## 2. 唯一执行动作（固定测试入口）

从验证分支的 `E:\NodeLab` 目录，在 PowerShell 用可用的 Python 3.12+ 解释器执行项目测试。**不得把 URI、密码或其他明文值传入命令行/环境变量。** 等价命令：

```powershell
$env:PYTHONPATH = 'E:\NodeLab\src'
$env:PYTHONDONTWRITEBYTECODE = '1'
py -3 -m pytest -q -p no:cacheprovider tests/test_p0_safety.py tests/test_windows_safety_gate.py
```

测试入口本身负责以下**断言**（不是让执行者自由设计检查脚本）：

- 在本机 E: NTFS 的受控私有根，写入**仅虚构随机 sentinel** 前验证根/新运行目录及新 YAML 文件的 DACL：当前用户 + SYSTEM 必要权限，无 Everyone/Users/Authenticated Users 广泛读取，无不安全继承或 reparse point/junction；ACL 错误应在秘密写入前 `PRIVATE_DIR_UNSAFE`。不修改/遍历已有真实 secret 文件；没有既有私有根时仅能创建安全根，不让用户先交出 `.secrets` 文件。
- `S1–S9` 的可执行安全负控：URI argv 禁止、allowlist/public/repr/错误 stdout/stderr 不含 sentinel 原值及编码变体，既有 URI/备注/path/Host/控制器 token/YAML 不因异常、列表/嵌套结构进入公共输出；所有密码都为本次生成的**虚构**值。
- 配置失败、Popen 失败、timeout、取消、子进程崩溃、正常完成各路径，始终只关闭本应用 own PID，等待有界且不留下本次私有明文目录；私有目录的 ACL 在运行中也要读回验证。单独启动的外部替身进程存活/其端口不变；**不按名称搜索/杀死**用户的 Mihomo。模拟旧 PID、恶意 reparse/异常归属时不得删除别人目录。
- 若测试实现对该阶段仍错误的业务配置使用假进程/假 controller，必须明确标为**安全生命周期测试**，不能据此宣布 Mihomo 协议、`-t`、控制器或逐请求路由已验收。Linux 单测通过与 Windows 这组真 DACL/PID 断言是两份独立证据。

Windows 上的安全关**不包含**首次真实 URI 探测、不要求用户已有 Mihomo 可用、不处理 `NL-003`。任何测试失败只回报固定项目名及状态；不要把包含动态 sentinel 的完整 traceback/YAML/日志/原始 PowerShell 历史粘贴到聊天、issue 或 GitHub。测试若向仓库写入了未知文件，立即报告 dirty，不自行 `git clean`。
