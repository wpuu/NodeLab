## 5. CLI 输入安全

当前：

`parse "<URI>"`
`probe "<URI>"`

把真实 URI 放进 argv，会进入 shell history / 进程参数。

本任务必须关闭该路径。

### 5.1 禁止 URI argv

产品 CLI 不再接受 URI positional argument。

推荐接口：

```text
python -m nodelab.cli parse-file --file <ABSOLUTE_LOCAL_PATH> --limit N
python -m nodelab.cli probe-file --file <ABSOLUTE_LOCAL_PATH> --limit N
python -m nodelab.cli parse-stdin
python -m nodelab.cli probe-stdin
```

如果为了兼容暂时保留旧子命令名：

- 旧 `parse <uri>` / `probe <uri>` 必须明确拒绝；
- 错误只输出固定 code；
- argparse/help/exception 不得回显 URI；
- 不得偷偷继续处理。

不要鼓励：

`echo "vless://..." | ...`

因为 PowerShell history 仍可能包含 secret。

stdin 仅作为程序能力存在，真实使用建议来自受保护文件重定向。

### 5.2 文件输入

文件路径可以进入 argv。

文件内容：
- 不打印；
- 不出现在 exception；
- 不出现在 public JSON；
- 不复制到仓库；
- 测试只使用 tmp path + 虚构 sentinel。

## 8. RunContext / 私有运行目录

设计一个单一 owner 的内部 RunContext（名称可以不同，但职责必须一致）。

其职责：

- run_id
- own Mihomo PID（若已启动）
- 当前 NodeLab 创建的 private run dir
- probe.yaml path
- cleanup state
- 不含 secret 的 recovery marker 所需元信息

### 8.1 Windows 私有根

真实 Windows 运行目录目标：

`E:\NodeLab.secrets\_runtime\<random_run_id>`

注意：
- 本任务不要求用户提前创建 `E:\NodeLab.secrets`；
- 测试可以在本机测试根目录中创建虚构目录；
- 绝不能用真实 URI。

实现必须：

1. 确认目标在 NTFS；
2. 拒绝 reparse point / junction / symlink；
3. 目录不能已存在；
4. 创建后设置受限 ACL；
5. 当前用户 + SYSTEM 允许必要访问；
6. Everyone / Users / Authenticated Users 不得有广泛读取；
7. 写明文 YAML **之前**验证 ACL；
8. ACL 失败：
   `PRIVATE_DIR_UNSAFE`
   且不得写 secret/YAML。

实现细节可使用 Windows 原生命令/标准库；
不得为了 T1 引入大型依赖。

### 8.2 非 Windows 自动测试

CI/非 Windows 测试可使用 tmpdir 模拟 lifecycle，并将 Windows ACL 检查抽象成可注入接口。

不得在 Linux 测试后宣称 Windows ACL 已验收。

## 9. 明文 YAML 生命周期

运行真实 Mihomo 时 YAML 必然包含凭据，这是允许的唯一短期明文例外。

必须满足：

```text
create safe run dir
→ verify safety
→ write config
→ validate/start/operate
→ finally
   → terminate only own process
   → bounded wait
   → kill only same own PID if needed
   → remove this run dir
   → verify removed
```

以下任一场景都必须测试清理：

- config write exception
- config validation fail
- Popen fail
- process early exit
- controller fail
- timeout
- KeyboardInterrupt / cancellation equivalent
- arbitrary exception
- normal success

如果 cleanup 无法确认：

`FAIL(SECRET_CLEANUP_FAILED)`

此前即使存在成功结果，也不得最终 PASS。

## 11. Crash Recovery 最小边界

T1 不要求做完整服务化恢复系统，但必须建立安全边界：

private root 中允许留一个**不含 secret**的 marker：

- run_id
- pid
- created_at
- expected exe canonical path/hash reference
- canonical run dir

再次启动时：

- 只能查看 NodeLab 自己的 private root；
- 不扫描全机；
- 只有能确认是本项目拥有的 PID 才允许终止；
- 无法确认：
  `RECOVERY_REVIEW_REQUIRED`
- 不得猜测性 kill。

若实现完整 recovery 会扩大 T1，可以只提供安全接口 + tests，不要做后台守护服务。

## 12. Adversarial Secret Matrix

每次测试随机生成 sentinel，例如：

`FAKE_ONLY_<random>`

不要只使用 UUID 格式。

必须覆盖至少：

### S1
Trojan password：
- 普通；
- 含冒号；
- percent-encoded `@`。

### S2
fragment/display name 包含 sentinel。

### S3
path / Host / SNI 包含 sentinel。

### S4
query：
- auth
- token
- Password
- password
- UUID
- 大小写混合。

### S5
- `%0A`
- newline
- multiline secret。

### S6
嵌套结构：
- dict
- list
- tuple
- key/value 中包含 sentinel。

### S7
模拟：
- subprocess stderr 含 sentinel；
- exception message 含 sentinel；
- HTTP error body 含 sentinel。

### S8
故障注入：
- config fail
- Popen fail
- timeout
- cancellation
- process crash

结束后：
- own process gone；
- private YAML/run dir gone；
- external fake process untouched。

### S9
CLI：
- 旧 URI argv 被拒绝；
- URI 不出 stdout/stderr；
- mixed valid/bad lines 不 crash；
- public JSON 不出现 sentinel。

所有测试最终扫描：

- stdout
- stderr
- public JSON
- repr
- exception surface
- temp artifacts after cleanup

不得出现：
- sentinel 原文；
- sentinel 典型 percent encoding；
- 可重放 URI。

不要为了测试而把 sentinel 写入 committed snapshot/golden file。
